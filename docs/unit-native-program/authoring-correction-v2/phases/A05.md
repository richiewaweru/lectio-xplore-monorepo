# A05 — Selection and upstream ownership
Dependencies: A01,A04

## Proposal and implementation scope
Remove backend semantic fallback maps. Use existing package/spec definitions and a single eligibility pipeline for ordinary and fallback candidates. Apply assets/readiness/writer support/budgets uniformly. Replace first-content and keyword-overlap policy with scoped semantic selection for ambiguous shortlists. Preserve exact selection snapshot and work-order identity. Verify teaching omissions result in targeted repair at the teaching stage rather than invented actions. Approved source binding requires compatibility with concept/objective/purpose, not first unused item. Follow existing approval rules if repair changes previously approved meaning; never silently revise it downstream.

## Acceptance gates
- **A05-G01**: Multiple eligible content/interaction options use configured selector; sole candidate selection remains deterministic.
- **A05-G02**: Out-of-shortlist decisions are rejected and boundedly repaired; reordered catalogue does not cause a first-entry policy choice.
- **A05-G03**: Required interactions/evidence cannot vanish; optional decisions follow explicit native policy.
- **A05-G04**: Fallback cannot restore candidates excluded for assets, budget, readiness, policy or writer support.
- **A05-G05**: Missing learner action/source causes owning-stage repair/error; no order-items default or first-unused-source assignment.
- **A05-G06**: Shared teaching inputs remain path-agnostic and both native outputs reference the same approved revision.
