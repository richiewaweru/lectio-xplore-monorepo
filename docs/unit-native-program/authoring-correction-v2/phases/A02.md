# A02 — Reusable authoring engine
Dependencies: A01

## Proposal and implementation scope
Implement a small reusable engine over existing provider abstractions. Accept scoped requests from package loaders. Support generate and convert-approved modes. Share provider invocation, parsing, validation, bounded repair and trace persistence. Keep specialized converters/validators/postprocessors pluggable. Retain original scope on repair. Use explicit test-provider injection only at external boundaries. Ensure native execution can await generation safely through existing workers; do not block event loops or create an alternate synchronous production shortcut.

## Acceptance gates
- **A02-G01**: Both package adapters run through one shared invocation/repair mechanism with their own schemas.
- **A02-G02**: Request capture proves unrelated schemas, catalogue data, other path settings and unrelated items are absent.
- **A02-G03**: Malformed response is repaired with original scope plus precise errors; exhaustion persists a typed failure.
- **A02-G04**: Missing inputs, unresolved definitions and unavailable provider fail rather than producing stubs.
- **A02-G05**: Result provenance records work order, source identities, teaching revision, definition and input hashes; retries are bounded.
