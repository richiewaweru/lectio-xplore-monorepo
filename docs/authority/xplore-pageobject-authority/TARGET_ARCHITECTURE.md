# Target Architecture

## 1. Ownership boundary

```text
XPLORE                                              LECTIO PAGE
──────────────────────────────────────────          ───────────────────────────
approved objective and concept cards                document schema
lesson/resource identity                            intent catalogue
lesson mode and prior-established knowledge         object catalogue
skeleton section purpose                            compatibility
candidate narrowing                                 physical capacity
block planning and evidence                         normalization
object-content generation                           structural validation
question generation behind the wall                 semantic validation
visual request orchestration                        renderer
variant visibility and audience policy              print CSS and PDF fixture
persistence and product lifecycle
```

Lectio may reject an invalid document. It must not decide what a worksheet means, what a learner already knows, or which variant sees a block.

## 2. Native v2 flow

```text

  ├─ compute real prior_established
  ├─ load lesson resource spec
  ├─ expand skeleton
  └─ create concept card + anchor
        │

        │
        ▼
section_block_planner(section context)
  ordered intent/object/evidence/brief
        │
        ▼
validate_block_plan
  closed candidates, compatibility, positions,
  section capacity, question/figure rules
        │
        ▼
object writers
  prose | list | table | worked-example | figure
  questions are assembled from item IDs
        │
        ▼
LectioDocumentV2 builder
        │
        ├─ backend JSON Schema validation
        ├─ backend semantic mirror checks
        └─ persist canonical v2 document
        │
        ▼

        │
        ├─ document_version=1 → legacy Lectio
        └─ document_version=2 → @lectio/page
        │
        ▼

```

## 3. Planning boundary

### Structural planner owns

- one concept card;
- anchor choice;
- section titles;
- transition notes;
- skeleton adherence;
- objective concern/deviation request.

### Section block planner owns

- number of blocks within the declared section min/max;
- ordered pedagogical intents;
- page objects compatible with those intents;
- evidence for each decision;
- concept-specific brief;
- layout placement only when allowed and justified;
- `slot_concern` if no valid plan exists.

### Object writer owns

- content fields of exactly one assigned object;
- adherence to the brief, object capacity, scope, terminology, and neighbouring-block context;
- no selection decisions.

### Document builder owns

- stable IDs;
- position/index normalization;
- section and document metadata;
- assembly of completed and pending blocks;
- final contract validation.

## 4. Heading hierarchy

```text
Document title             h1, generated by document renderer
Section title              h2, generated from section.title
Nested heading object      h3, optional and structural, no intent
```

The initial planner does not receive `heading` as a candidate object. This avoids duplicate section titles while preserving a future nested-heading capability.

## 5. Persistence states

A v2 generation may persist these states:

```text
PLANNED
  structural_plan contains PlannedBlock records

WRITING
  individual blocks have statuses pending|writing|ready|failed

DOCUMENT_READY_WITH_PENDING_MEDIA
  content document is valid; figure assets may be pending

COMPLETE
  all required blocks and media resolved; final validation green

FAILED
  machine-readable failure at planner, writer, assembly, validation, or render gate
```

The persisted canonical document must be renderable after process restart. Do not reconstruct it from transient events.

## 6. Compatibility and validation

Validation layers:

1. Pydantic output validation for planner/writer responses.
2. Candidate closure: selected intent/object must be in the supplied matrix.
3. Catalogue compatibility.
4. Object capacity and layout rules.
5. JSON Schema validation of the assembled document.
6. Semantic validation mirroring Lectio checks.
7. Browser-render validation and print scan.
8. Optional LLM quality review, never a substitute for deterministic gates.

## 7. Coexistence

```text
Generation/document metadata
  document_version: 1 → existing path, existing renderer
  document_version: 2 → native page path, @lectio/page
```

The same application deployment supports both. The v2 feature flag controls creation, not reading. Once a v2 document exists, reading it must not require the generation flag to remain enabled.
