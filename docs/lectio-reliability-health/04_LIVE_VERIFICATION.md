# Live verification protocol

## Early, before implementation
Use prompts/00_LOGIN_FIRST.md immediately. Start application/services through repository-documented commands; verify URLs and served revision rather than guessing. Inspect environment config without displaying secrets. In Casa by Grok's actual browser, authenticate and verify an authorized page. Record readiness while the user is awake. Session availability in another machine/browser is not evidence. No exporting credentials into this pack.
Attempt a baseline fresh Unit workflow now. If it fails, retain the failure and don't relabel resumed fragments as a continuous fresh success. Preserve the authenticated context/profile through subsequent phases using supported browser facilities, with normal expiry respected. No permanent tokens, auth bypass, session-lifetime extensions or artificial keepalive loops. Login early reduces risk but cannot guarantee overnight availability.

## Final on exact implementation commit
1. Record commit, services/build identifiers, browser context reference, environment and sanitized provider configuration. Use isolated test data; never kill a production worker.
2. Create a fresh Unit through UI. Plan/approve structure and teaching through normal interfaces. Use naturally generated learner actions. Record Unit, preparation and teaching revision IDs.
3. Generate Learn via real admission route; verify real LLM composition and six-primitives document structure with retained sections and stable IDs. Open Builder, edit/save/reload, explicitly publish test release, enter a natural interaction, verify evaluation and reload persisted attempt. Capture linked request/run/release/attempt identities. No seeded document substitutes.
4. Generate Print as sibling from the SAME approved revision. Open native editor, change text with unique marker, save/reload and prove revision increment. Issue a genuine stale competing edit and prove 409 with preserved local edit. Export exact edited revision, retain PDF binary, render/inspect pages and extract marker text. Compare Learn artifact content hash/revision before and after, not only updated_at.
5. Refresh and disconnect/reconnect UI while work runs; verify accurate status and one logical operation. Repeat admission with the same key and prove one job/artifact.
6. In disposable test environment interrupt a worker after completed node checkpoints; restart and verify unchanged IDs/hashes and no new calls for completed nodes. If crash occurs after external call but before commit, report ambiguous outcome honestly. Test expired worker commits are rejected. Fail one path while the sibling completes.
7. Controlled provider failure scenarios should use an explicit test-only adapter for deterministic 429/timeout/invalid JSON cases. Label those INJECTED, separate from REAL_PROVIDER generation evidence. Verify strict attempt cap and visible recovery. Never claim a real outage was observed when injected.
8. Check cancellation and a recoverable media failure. Text remains saved; missing required media prevents false full completion, and optional media follows declared policy with visible status.

## Evidence
One run-manifest.json links every step, timestamp, method (UI/API/injected), input/output IDs, exact revision/hash and result. Keep screenshots showing actual UI stages/edit conflicts; sanitized event trace; raw command logs; provider-call accounting; PDF + extracted text + rendered inspection notes. Include failed attempts and resumes, not just final successful stamps. Hash artifacts. No passwords, cookies, bearer tokens or raw sensitive learner data. Live failures block corresponding gates; document and repair before retrying. If auth expires while user sleeps, record BLOCKED and continue offline work without bypassing authentication.
