# Implementation Phases

> **Superseded for restructure work:** Stage-2 speed, nominated merge critic, prompt packaging, and constructor/readback UI are owned by [`RESTRUCTURE_HANDOFF.md`](RESTRUCTURE_HANDOFF.md). Prefer that document over the phase checklist below for those items.

## Phase 0 — Baseline

- capture `xplore` commit;
- run backend, frontend, architecture gates;
- save current live fixtures;
- add runbook.

## Phase 1 — Fix silent defects

- live role validation replaced by skeleton slot validation;
- component cognitive jobs reach selector;
- StructuralPlan strict again;
- explicit legacy adapter;
- misconception quota 0–3 for new path lessons.

**Gate:** regressions pass; legacy fixtures still load.

## Phase 2 — Irreversible additive foundations

- concepts table;
- canonical concept references;
- path objective ownership contract;
- provenance fields;
- objective hash.

**Gate:** existing generation behavior unchanged.

## Phase 3 — Skeleton data and preview

- install/validate `skeletons.yaml`;
- slot/component map;
- knowledge-type classifier;
- preview endpoint;
- secondary demand;
- deviation schema.

**Gate:** zero output behavior change.

## Phase 4 — Shadow logging

- log skeleton preview beside current StructuralPlan;
- reviewer comparison surface/report;
- gather 30 real lessons.

**Decision gate:** continue, revise taxonomy, or stop.

## Phase 5 — Unit/path backend

- units;
- scope contracts;
- path versions;
- path planner;
- concept resolution;
- split/merge/skip/replan/approve;
- no hard lesson/time count.

**Gate:** Grade 4/12 fixtures; no silent prerequisite dropping.

## Phase 6 — Path-to-Xplore bridge

- single-card plans;
- skeleton expansion;
- immutable objective;
- existing review halt;
- existing items/variants/QC/print.

**Gate:** compare path-prepared lesson with current whole-session planner.

## Phase 7 — Existing-UI validation

Before building large UI:

- expose unit/path data in a minimal existing surface;
- prepare several real lessons;
- collect teacher review.

**Go/no-go gate:** path-planned flow must be meaningfully better.

## Phase 8 — Path UI

## Phase 9 — Teaching schedule

- time feasibility;
- drag/drop;

## Phase 10 — Controlled variants UI

## Phase 13 — Convergence
